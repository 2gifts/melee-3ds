See [update 11 details](BOTTOM_SCREEN_UPDATE_11.md).

Update 11's bottom screen still needs physical validation. Stable 60 rendered FPS across gameplay remains unverified; simulation rate is a separate measurement.

## Current implementation

The engine uses 32-bit ARM BE8 data and retains original GameCube struct/bitfield layout. SDK calls cross explicit endian/ABI bridges. Compile-time checks include four-byte engine bool/enums, pointer size, Fighter, HSD_JObj, HSD_Archive, PADStatus and HSD_TECnst. SDK objects retain libctru's packed enums and one-byte bool. BE8 relocation words are now finalized in the linked image before 3DSX packaging, and removed from the little-endian loader's relocation records. Native relocations remain standard. Startup verifies the actual text/rodata/data addresses against the built layout before entering engine code. This targets the modern Luma loader's contiguous layout at 0x100000 and avoids all runtime patching of protected code/constants.

Source overlays correct absolute GameCube address assumptions and several dependencies on neighboring linker globals: shared card context, SFX-bank storage, fighter material templates and the effect parameter table. The latter was corrupting the effect allocator during CPU attacks; its original functions now use their intended table and pass a host regression that guards adjacent memory. Deferred DVD/ARAM callbacks preserve original loader sequencing. Cooperative polling allows the original sound-bank and scene-loading state machines to progress.

Versus testing exposed two more adjacency assumptions: the item-container drop table and the results camera/display data. Both now use explicit table references or one shared allocation. Results tables match the original DOL bytes, and compile-time checks protect display offsets. The character-to-animation lookup also had an uninitialized ordinary-character value; the original PPC instructions retain the input ID on that path. Its overlay passes 396 character/form/costume cases and fixes incorrect character labels.

Five player functions also treated two filename strings and the character mapping as one allocation. They now access `ftMapping_list` directly. All 99 table bytes match the supported DOL; host checks exercise all 33 entries for demo archives, secondary fighters, transformations, falls and slot types. Item helpers for freeze-spawn positioning and Link's arrow now initialize explicitly optional pointers before their documented absent-input paths.

The damage-effect helper also had an undefined return when temporary damage was zero. Original DOL instructions return the nonzero caller address on that path; its adapted C now preserves that boolean result explicitly. The actual adapted function passed 1,280 damage/element/level/callback-result cases, with the relevant PPC instructions checked against the supported DOL (`tools/test_damage_return.py`).

Runtime adapters implement heaps, OS context switching, message queues, alarms, virtual interrupts, SD DVD reads, virtual ARAM, PAD and VI timing. The AX mixer handles ADPCM/PCM voices, pitch, volume and loops, with NDSP output. ADPCM prediction now retains a wide accumulator before rounding and saturation; 1,679,616 boundary combinations passed an independent arithmetic reference.

Sample-rate conversion now uses linear interpolation with fractional phase and four-sample history preserved across audio blocks. A reference ramp checked 1,152 samples across 12 ratios, plus block continuity and direct-sample mode. The original DSP's polyphase interpolation filter remains unimplemented.

An explicit `--smoke --audio-hle` build exercises Azahar's NDSP shared-memory protocol using a placeholder component. Azahar HLE does not execute DSP instructions. This fixture contains no physical DSP program, and release builds reject the option. `tools/audio_capture_test.py` captures the actual final NDSP stereo mix. Earlier mutable-ring captures could include debugger interference; current captures freeze a complete new ring on its producer thread and reject debugger polling during that window. Physical audio, synchronization during loading, resampling fidelity and optional auxiliary effects remain unverified or unfinished.

Periodic pad sampling now preserves its scheduled phase across expensive draws. It bounds recovery after long I/O stalls and shares clock reads across cooperative timer services. The original game loop can consume multiple queued simulation updates before drawing. The earlier test tools counted displayed engine frames; their `--seconds` labels therefore did not measure simulation seconds. New fighter traces include the original simulation counter, and the CPU test now measures 60 simulation updates per requested second.

The renderer translates GX triangles, strips, fans and quads to PICA200 indexed batches. GX points expand in a geometry shader after vertex lighting and projection. GX lines and line strips have a CPU expansion path with depth clipping, axis-aligned caps and texture offsets. Matrix palettes, two raster color channels, diffuse/spot/specular lighting and common affine materials run in the GPU vertex shader. The shader fits four light/channel contributions into the PICA uniform budget; more complex cases retain a CPU evaluator. Final material clamps are separate from intermediate clamps, preserving the diffuse-plus-highlight fast path. GX specular channel setup forces diffuse mode NONE as in the original SDK.

The point shader matched CPU-expanded reference quads pixel-for-pixel in 64 offscreen cases covering sizes, texture offsets, colors, perspective depth and clipping (`build/point-gpu-test.json`). Both framebuffer-copy reference checks passed after switching between geometry and ordinary shader programs. Fountain of Dreams contains roughly 25,000 points per frame in its original display lists; these are now rendered rather than omitted.

GX front/back/all face culling is implemented. Lines and points bypass polygon culling; their batch transitions flush before changing topology. Native culling matches signed-area selection in 32 offscreen cases, including both windings and perspective scales (`build/cull-gpu-test.json`). Blending now distinguishes source and destination color factors, applies the same GX equations to alpha, substitutes one for destination alpha on RGB targets, and implements reverse subtraction and all 16 logic operations. The 148-case GPU blend fixture matched the independent arithmetic reference pixel-for-pixel (`build/blend-gpu-test.json`); 524,288 host cases cover factor selection. These tests do not establish exact GX six-bit framebuffer quantization or destination-alpha replacement.

Decoded geometry has a bounded cache that checks its source display list and indexed arrays before reuse. A second bounded cache retains converted vertices in GPU-accessible memory, protecting resources referenced by the current GPU frame. The live validation mode has compared hundreds of thousands of cached batches to fresh decoding during animation and controller input. Shader uploads skip unused matrix rows and inactive lights.

Flat material colors are now live shader constants. Two-row texture transforms exclude an unused third row from their geometry cache key and explicitly produce Q=1. That unused row was changing between unrelated draws and repeatedly invalidating the large stage point list. The corrected cache passed 165,710 batch comparisons and 135,664 material comparisons during a Training controller run (`build/point-cache-fix-reference.json`). Fixed-size original-engine memory operations also use compiler intrinsics, with residual calls retained through the BE8 library.

Material results also have a bounded cache keyed by all inputs to their TEV evaluation. A live test compared 283,534 cache hits against fresh results and 269,644 cached geometry batches against fresh decoding (`build/material-cache-reference.json`).

Shadow and refraction texture copies can stay on the GPU: native tile-row DMA followed by a crop/format draw replaces the CPU readback. Other copy consumers retain their CPU-visible GameCube layout. `tools/efb_copy_test.py` captured the exact source and destination of an actual shadow copy and a synthetic full-color RGB565 copy. Both matched every reference pixel at the destination format's precision. The synthetic check exercises conversion without changing game state; it does not establish that the complete invisibility/refraction effect is correct.

Ordinary textures now have a 16 MiB budget. Completed-frame textures are evicted by age; if a frame needs more than fits, a GPU completion barrier makes its earlier textures safe to evict. Direct-color textures no longer include unrelated TLUT state in their keys. Native intensity, intensity/alpha and RGB565 storage reduces allocation size without changing decoded precision. Camera scissor rectangles are applied on the rotated PICA target; 30,000 rectangles matched an independent pixel-center reference. GPU copy-clear uses its own rectangle.

CMPR decoding now uses the GameCube's 5:3 interpolation weights and retains average RGB in the transparent entry. RGB565/RGB5A3 expansion uses bit replication. All 131,072 packed color words and 1,834,176 pixels across 256 padded/tiled CMPR textures passed independent reference comparisons. Endpoints are decoded once per 4×4 block directly into PICA tiles. Both GPU EFB-copy checks still match at the destination format's precision (`build/cmpr-stream-reader-efb-reference.json`). [Dolphin's texture decoder](https://github.com/dolphin-emu/dolphin/blob/master/Source/Core/VideoCommon/TextureDecoder_Generic.cpp) documents the CMPR semantics.

The transient vertex/index allocation was reduced from 196,608 to 16,384 vertices, saving about 10.7 MiB of linear memory. When needed, queued GPU draws finish before those ranges are reused; game color/depth buffers and persistent geometry survive. The larger texture cache is funded from that saving. The observed Zelda/Ice Climbers run used about 10.2 MiB of textures and retained roughly 12.7 MiB of free linear memory. A 512-vertex stress limit forced 256 additional buffer reuses over 101 displayed frames while all point, culling, blend and EFB-copy reference checks remained pixel-exact (`build/streaming-buffer-test.json`).

A smoke-only pressure test reduced the ordinary texture budget to 1 MiB for 93 displayed frames, forcing 558 completion barriers while the original match advanced without a failure (`build/texture-budget-test.json`). It restored the normal budget afterward. Both EFB copy reference checks still passed following this run.

The TEV pipeline still approximates multi-texture materials, reflections and shadows. Destination-alpha replacement, additional GX state and exact framebuffer precision also need work. These limitations affect appearance and prevent a faithful-graphics claim.

The separate `renderer optimization 1` update adds a 512-bucket texture index using 1,536 bytes of ordinary memory. It retains the existing identity keys, retired-texture handling and dense-array eviction. A host test covered worst-case collisions and 20,000 insert/retire/compact operations. Live indexed lookups matched the original linear scan 61,712 times while a 1 MiB pressure limit forced 74 texture completion barriers (`build/texture-index-live-test.json`).

Normal draws also retain culling, scissor, texture-environment, depth, blend and simple-alpha state across adjacent batches. Frame-target changes and EFB copies invalidate the retained values; complex alpha passes invalidate the simple-alpha value. Texture objects are still rebound because eviction can move their slots. Citro3D's setters otherwise reupload unchanged state. The actual draw bridge produced identical pixels with the optimization enabled and disabled across 160 cases, each with three overlapping draws, including a real EFB copy and copy-clear. The comparison remained exact under a 512-vertex streaming limit (`build/raster-state-stream-fixture-reference.json`). Existing point, culling, blend and EFB reference checks also passed under buffer pressure (`build/raster-streaming-reference.json`).

## Tests and limits

Host checks passed for the affine shade compiler, exhaustive alpha predicate reduction/stencil truth logic, fixed-point and unaligned float vertex decoding, and aligned/unaligned/overlapping memory operations. The effect parameter regression compiles the actual generated source overlay. Existing archive and extraction tests cover malformed input bounds. Every engine build executes compile-time ARM ABI checks.

Additional checks cover periodic timer phase/recovery, native texture storage precision, item-container table writes, original results data, character lookup and scissor conversion. An uninitialized-local audit flagged 19 original game/HSD source files for further review; warnings include paths guarded by game invariants and are not automatically treated as confirmed defects.

Screenshots and original-engine state traces are available under `build/`. Emulator timing is used for relative profiling only: Azahar reports New 3DS CPU speed configuration as unimplemented. At its 100% CPU setting, a Mario/Mario Fountain test advanced about 18 simulation updates and 8.6 renders per emulated second before the timer change, versus 44 updates and 8.8 renders afterward (`build/match-profile-before-timers.json`, `build/match-profile-after-timers.json`). These are different quantities; neither is a physical console frame-rate or latency measurement.

`tools/compare_shading.py` captures CPU and GPU evaluations for visual review. Training's pause screen continues animation, so its whole-image difference metrics are not a deterministic shader-equivalence test; the temporal differences are substantial too.

Further emulator tests used a 300% CPU budget because Azahar does not implement the New 3DS speed request. An active CPU sample measured about 52 simulation updates and 18 renders per emulated second (`build/match-profile-cpu300-active.json`). This setting is an experiment, not a validated model of physical New 3DS performance. Full Versus runs above used this setting.

With the stage's points present, an initial GPU-point sample measured 52.94 simulation updates and 12.85 renders per emulated second. Correcting the texture-transform cache key brought a subsequent sample to 52.46 updates and 20.54 renders, with HLE audio enabled (`build/match-profile-gpu-points.json`, `build/match-profile-point-cache-fix.json`). These samples used the same stage and 300% setting but different match moments; they are profiling evidence, not controlled hardware benchmarks or a full-speed claim.

Zelda/Ice Climbers exceeded the old 8 MiB texture budget, forcing texture conversion and GPU completion barriers almost every render. A live 8→12→8 MiB experiment measured 5.85→49.96→7.77 simulation updates and 1.17→19.15→1.74 renders per emulated second; the middle sample had no texture barriers (`build/texture-capacity-profile.json`). The final 16 MiB cache with streamed vertices measured 51.50 simulation updates and 21.60 renders in Training (`build/match-profile-streaming.json`), and a subsequent Versus sample measured 49.43 and 20.58 respectively (`build/match-profile-audio-buffered.json`). Match moments differ, and the 300% emulator setting still does not establish console speed.

The streamed renderer passed another 1,800-update CPU combat run and 190,110 geometry / 152,315 material comparisons against fresh evaluation (`build/streaming-cpu-reference.json`, `build/streaming-cache-reference.json`). Audio starts or restarts after accumulating 48 ms of already-produced PCM. Four original 3 ms AX slices are combined into each 12 ms NDSP buffer. [libctru submits up to five buffers to the DSP](https://github.com/devkitPro/libctru/blob/master/libctru/source/ndsp/ndsp-channel.c), so this increases the DSP-visible coverage from 15 to 60 ms without increasing the startup target. A host ownership test exercised 20,004 buffers, partial writes, full-queue drops, wraps and recovery without changing queued PCM.

Tracing then identified roughly 50 ms disc reads during combat. The native DVD adapter now retains at most eight open streams with 64 KiB read buffers, closes them on exit, and avoids redundant seeks on sequential reads. The total read-buffer budget is 512 KiB of ordinary memory. Its host test covers sequential/backward/buffer-crossing reads, EOF padding, 1,000 reads across 20 files forcing eviction, invalid paths/offsets and close/reopen.

With the stream cache, two Zelda/Ice Climbers captures observed maximum disc reads of about 12.54 ms, zero capture-window underruns, and no all-zero stereo run longer than one sample (`build/stream-reader-audio-reference.json`, `build/stream-reader-audio-repeat-reference.json`). Their measured maximum mixer gaps were 16.52 and 18.55 ms. Earlier captures without the cache still had long gaps even with grouped audio buffers. A subsequent sample measured 59.78 simulation updates and 24.10 renders per emulated second (`build/stream-reader-profile-reference.json`). These short emulator samples do not establish uninterrupted playback over a whole match or physical console speed.

The hardware alpha has physical controls, original startup, SD assets, a controls screen and SELECT exit. It has no automatic pad sequence. The first physical New 3DS test crashed during the old startup relocation loop; the user confirmed that `hardware startup fix 1` boots with music and sound effects. `menu rendering fix 2` addresses the subsequently reported invisible menu geometry. Full speed, complete roster/stage coverage, all modes, saving and multiplayer remain unfinished or unverified. Optional video playback is unfinished.

## Work in progress

Texture processing averaged 4.90–4.93 µs per draw on the original path, 3.92 µs with the index alone, and 4.07 µs with both changes. GPU command generation fell from about 7.09 to 5.60 µs per draw. This establishes lower CPU cost in the measured phases, not a demonstrated frame-rate increase or physical console speed (`build/raster-optimization-profile.json`). Debugger pauses contaminate the cumulative session counters; only the uninterrupted capture window supports that audio result.
